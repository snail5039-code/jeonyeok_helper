# 배포 가이드

> 2026-10-18 정리. 가격은 이날 확인한 대략값이라, 결제 전에 각 회사 가격 페이지에서 다시 확인하세요.
> 결론부터: **서버 한 대(4GB) + docker compose + Caddy(무료 HTTPS)** 가 지금 구성을 그대로 올릴 수 있고 가장 싸고 단순합니다. AWS라면 **Lightsail 4GB(월 약 $24)** 를 추천합니다.

## 1. 이 서비스가 필요한 것

| 구성 | 하는 일 | 측정한 메모리 (로컬 Docker, 대기 중) |
|---|---|---|
| `db` PostgreSQL 17 + pgvector | 검색 자료(10,143 조각), BM25 색인, 대화·프로필·작전도·알림 구독·운영 기록 | 약 300MB (DB 크기 198MB) |
| `api` FastAPI + LangGraph | 답변, MCP 도구, 기한 알림 보내기(한 시간마다) | 약 830MB (BM25 색인·Kiwi 형태소 분석기 포함) |
| `refresh` | 7일마다 바뀐 법령·조례만 다시 수집, 검색 평가 | 돌 때만 수백 MB |
| `web` Next.js | 화면, `/api/*` 중계 | 약 80MB |

- **메모리 4GB 권장.** 대기 중 약 1.2GB지만 갱신·이미지 빌드 때 더 씁니다. 2GB 서버는 스왑(2~4GB)을 꼭 켜고, 이미지는 다른 곳에서 빌드하는 게 안전합니다.
- **디스크 20GB 이상.** 이미지 약 1.3GB + DB + 로그·백업.
- **HTTPS 필수.** 브라우저 알림(Web Push), 홈 화면 설치(PWA), 서비스 워커는 HTTPS에서만 동작합니다. 그래서 **도메인**이 필요합니다(연 1~2만 원).
- **외부로 나가는 요청:** Gemini API, 국가법령정보센터, 공공데이터포털, 온통청년, 푸시 서비스(FCM·애플·모질라). 들어오는 포트는 80·443만 열면 됩니다.
- **비용은 서버만이 아닙니다.** Gemini API 사용료가 질문 수에 비례해 붙습니다(질문 하나에 모델 호출 5~8번). Google AI Studio에서 결제 한도·알림을 먼저 걸어 두세요.

## 2. 배포 전 체크리스트

### 코드·설정 (배포 전에 레포에서 할 것)

| | 할 일 | 왜 | 상태 |
|---|---|---|---|
| ☐ | **DB 비밀번호를 비밀값으로** — `docker-compose.yml`의 `jeonyeok:jeonyeok`을 `.env`의 `POSTGRES_PASSWORD`로 | 지금은 개발용 비밀번호가 파일에 적혀 있음 | 할 일 |
| ☐ | **HTTPS 앞단(Caddy) 추가** — `caddy` 서비스 + `Caddyfile`(도메인 → `web:3000`), `web`의 `3000:3000` 공개 포트는 빼기 | 무료 인증서(Let's Encrypt) 자동 발급·갱신 | 할 일 |
| ☐ | **이용약관·개인정보처리방침 화면** | 익명 ID, 대화 내용(개인정보 형식은 가림), 알림 구독, 운영 기록을 저장함. 보관 기간(운영 기록 90일 등)·삭제 요청 방법을 적어야 함 | 할 일 |
| ☐ | **`py-vapid` 올리기** (2026-10-28 이후) | 1.9.5·1.9.6이 배포된 지 2주가 안 돼 1.9.4로 묶어 둠 | 10-28 이후 |
| ☑ | 관리자 화면 검색 노출 막기, 관리자 열쇠 없으면 꺼짐 | | 완료 |
| ☑ | 횟수 제한이 중계 뒤에서도 사용자별로 (X-Forwarded-For + 전체 상한) | | 완료 |
| ☑ | 서버는 한 프로세스(uvicorn 워커 1개)로 | 기한 알림 루프가 워커마다 돌면 알림이 겹칠 수 있음. 지금 Dockerfile이 1개로 띄움 | 완료 (늘릴 땐 알림 루프를 따로 빼야 함) |

### 서버 `.env` (서버에서 직접 만들고 Git에는 올리지 않음)

| 키 | 값 |
|---|---|
| `GOOGLE_API_KEY`, `LAW_API_OC`, `DATA_GO_KR_SERVICE_KEY`, `YOUTHCENTER_API_KEY` | 로컬과 같은 값 (또는 운영용으로 새로 발급) |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | 로컬 값을 그대로 쓰거나 새로 생성 (`npx web-push generate-vapid-keys`). 바꾸면 기존 알림 구독은 다시 받아야 함 |
| `VAPID_SUBJECT` | **`https://내도메인`** (경로 없이) 또는 `mailto:주소`. 지금 로컬 값 `https://localhost`는 운영에서 쓰면 안 됨 |
| `ADMIN_TOKEN` | **운영용으로 새로 생성** (`python -c "import secrets; print(secrets.token_urlsafe(24))"`) |
| `POSTGRES_PASSWORD` | 새로 생성한 긴 값 (위 compose 변경 후) |
| `CHAT_RATE_LIMIT_PER_MINUTE` | 기본 20. 비용이 걱정되면 낮춤 |

### 데이터 옮기기

검색 자료(법령·조례 임베딩)를 서버에서 다시 수집하면 시간과 임베딩 비용이 듭니다. **로컬 DB를 덤프해 그대로 옮기는 것**을 권장합니다.

```bash
# 로컬
docker exec jeonyeok_helper-db-1 pg_dump -U jeonyeok -Fc jeonyeok > jeonyeok.dump   # 약 200MB
scp jeonyeok.dump 서버:~/

# 서버 (db만 먼저 띄운 뒤)
docker compose up -d db
docker compose exec -T db pg_restore -U jeonyeok -d jeonyeok --clean --if-exists < jeonyeok.dump
```

- 로컬에서 시험으로 만든 사용자 기록(측정·캡처용 `measure-*`, `readme-*` 등)도 같이 옮겨지니, 깨끗하게 시작하려면 서비스 표(`journey_item`, `chat_run`, `feedback`, `push_*`, `resume_code`, LangGraph 체크포인트·스토어)는 비우고 검색 자료(`langchain_pg_*`, `cache_entry`, `source_version`)만 남기세요.
- 보훈부 PDF 원본(`backend/data/raw/`)은 Git에 없습니다. 덤프로 옮기면 필요 없고, 다시 수집할 때만 서버에 복사합니다.

## 4. 방법 A: AWS Lightsail (추천)

1. **계정과 도메인** (직접): AWS 가입·결제 수단 등록, 도메인 구매(가비아·Route 53·Cloudflare 등).
2. **인스턴스 만들기**: Lightsail → Create instance → 리전 **서울(ap-northeast-2)** → Linux, **OS only: Ubuntu 24.04** → 플랜 **4GB** → 이름 `jeonyeok`.
3. **고정 IP**: Networking → Create static IP → 인스턴스에 연결 (무료, 연결돼 있을 때).
4. **방화벽**: Networking 탭에서 **HTTP 80, HTTPS 443** 열기. SSH 22는 가능하면 내 IP만.
5. **DNS**: 도메인 관리 화면에서 `A 레코드: 도메인 → 고정 IP`.
6. **서버 준비** (SSH 접속 후)
   ```bash
   sudo apt update && sudo apt -y upgrade
   curl -fsSL https://get.docker.com | sudo sh
   sudo usermod -aG docker $USER && newgrp docker
   # 메모리가 빠듯할 때를 대비한 스왑 4GB
   sudo fallocate -l 4G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
   echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
   ```
7. **코드와 키**
   ```bash
   git clone https://github.com/snail5039-code/jeonyeok_helper.git && cd jeonyeok_helper
   cp backend/.env.example backend/.env && nano backend/.env   # 2장의 표대로
   ```
8. **데이터 옮기기**: 2장 '데이터 옮기기'대로 덤프 복원.
9. **띄우기**
   ```bash
   docker compose up -d --build
   docker compose ps                 # 모두 healthy인지
   curl -s https://도메인/api/health   # {"status":"ok", ... "vapid": true}
   ```
10. **배포 후 실테스트**: 6장 체크리스트.

비용을 더 줄이려면 2GB 플랜(약 $12)도 가능하지만, 스왑을 켜고 이미지를 GitHub Actions에서 빌드해 GHCR에서 받아 오는 방식으로 바꾸는 게 좋습니다(서버에서 Next.js 빌드가 메모리를 많이 씀).

## 5. 다른 방법 요약

### B. AWS EC2
Lightsail과 순서는 같고 다음이 다릅니다.
- 인스턴스: **t4g.medium**(ARM, 2 vCPU·4GB) — 이미지가 ARM에서도 빌드되는지 확인(Python·Node 공식 이미지는 ARM 지원). x86이 편하면 t3.medium.
- 디스크: EBS gp3 30GB. 고정 IP는 **탄력적 IP**.
- 보안 그룹: 인바운드 80·443(전체), 22(내 IP).
- 백업: EBS 스냅샷 또는 `pg_dump` → S3(수명 주기 규칙으로 30일 뒤 삭제).
- 나중에 키울 때: DB를 RDS PostgreSQL(pgvector 확장 켜기)로, 앞단을 ALB + ACM 인증서로 바꾸면 서버를 여러 대로 늘릴 수 있습니다(그때는 기한 알림 루프를 한 곳에서만 돌게 분리).

### C. Oracle Cloud 무료
- Always Free의 Ampere A1(ARM) VM. 2026년에 무료 한도가 2코어·12GB로 줄었다는 글이 있으니 가입 전에 공식 문서를 확인하세요. 그래도 이 서비스에는 충분합니다.
- 인기 지역(춘천·서울)은 자리가 없을 때가 많아 여러 번 시도해야 할 수 있습니다.
- 이후 순서는 A의 6~10번과 같습니다(Ubuntu ARM). 오라클은 VCN 보안 목록과 서버 안 `iptables` 둘 다 80·443을 열어야 합니다.

### D. 국내 클라우드 (네이버 클라우드·카카오클라우드·KT Cloud)
- 2~4코어·4~8GB 서버를 만들고 A의 6~10번과 같이 진행합니다.
- 개인정보를 국내에만 둔다고 설명할 수 있어, 보훈 관련 기관과 협업·제안할 때 유리합니다.

### E. PaaS (Render·Railway·Fly.io)
- `docker-compose.yml`을 그대로 못 쓰고 `api`·`web`·`refresh`를 각각 서비스로 만듭니다. `refresh`는 크론 작업(주 1회 `jeonyeok-rag refresh`)으로 바꾸면 됩니다.
- DB는 **pgvector를 지원하는** 관리형 Postgres를 골라야 합니다(예: Neon, Supabase, 각 PaaS의 Postgres — 확장 지원 여부 확인).
- `web`의 `API_URL`을 `api` 서비스 내부 주소로 설정합니다.

### F. 집 PC + Cloudflare Tunnel (시연·실기기 테스트용)
```bash
docker compose up -d
cloudflared tunnel --url http://localhost:3000   # 임시 https 주소가 나옴
```
- 도메인을 Cloudflare에 연결하면 고정 주소도 됩니다. 휴대폰 알림·PWA를 **실서버 없이 먼저 확인**하는 데 좋습니다. `VAPID_SUBJECT`는 그 주소로.

## 6. 배포 후 실테스트 체크리스트

| | 확인 | 어디서 |
|---|---|---|
| ☐ | `https://도메인`이 열리고 자물쇠(인증서)가 보임 | PC |
| ☐ | 질문 → 찾은 자료가 먼저 보이고 → 근거와 함께 답, [n]을 누르면 원문 | PC·휴대폰 |
| ☐ | 작전도 만들기 → "했어요" → 계급이 오름 | PC |
| ☐ | 신청 서류 도우미 5개 제도, 관할 보훈청이 내 지역으로 | PC |
| ☐ | **캘린더에 넣기**: 받은 `.ics`가 구글·애플·아웃룩 캘린더에 추가되고 알림 시각이 맞음 | 휴대폰·PC |
| ☐ | **알림**: 안드로이드 크롬·PC 크롬에서 알림 켜기 → 시험 알림 받기 → 누르면 작전도 | 안드로이드·PC |
| ☐ | **아이폰**: 사파리 → 공유 → 홈 화면에 추가 → 홈 화면 앱에서 알림 켜기 → 시험 알림 | 아이폰 (iOS 16.4 이상) |
| ☐ | 이어 하기 코드·QR로 다른 기기에서 같은 작전도가 열림 | PC → 휴대폰 |
| ☐ | 기록 파일 저장 → 다른 브라우저에서 불러오기 | PC |
| ☐ | `/admin`이 운영용 열쇠로만 열리고, 질문 기록이 쌓임 | PC |
| ☐ | `docker compose logs refresh`에 갱신 기록, 일주일 뒤 `refresh_run`에 결과 | 서버 |
| ☐ | 서버 재시작(`sudo reboot`) 뒤 자동으로 다시 뜸 | 서버 |

## 7. 업데이트와 되돌리기

```bash
cd jeonyeok_helper
git pull
docker compose up -d --build        # DB 스키마는 api가 켜질 때 자동으로 최신까지 (Alembic)
docker compose logs -f --tail=100 api
```

- 되돌리기: `git checkout 이전커밋 && docker compose up -d --build`. DB 마이그레이션이 들어간 변경을 되돌릴 땐 먼저 백업을 복원하세요(마이그레이션은 앞으로만 자동 적용).
- 큰 변경 전에는 `pg_dump`로 백업을 하나 더 남깁니다.
