# 전역도우미 개발 순서

> 🔑 = API 키가 필요한 단계. 키가 없는 동안에는 샘플 데이터와 가짜(mock) 응답으로 먼저 만들고, 키를 넣으면 실제 데이터로 바꾼다.

---

## 0단계. 프로젝트 준비
- [ ] 폴더 구조, `pyproject.toml`, `.env.example`
- [ ] Git 저장소 만들고 GitHub `jeonyeok_helper` 레포에 올리기
- [ ] GitHub Actions **CI**: push마다 테스트 자동 실행

## 1단계. RAG (규정 검색)
- [ ] 법령 수집기: 국가법령정보센터 API → 조문 단위로 자르기 🔑 법령 OC
- [ ] 지자체 조례 수집기 (자치법규) 🔑 법령 OC
- [ ] 국가보훈부 파일 로더 (PDF 등)
- [ ] Chroma 벡터 DB에 저장 (Gemini 임베딩) 🔑 Gemini
- [ ] 검색 고도화: **HyDE**, **Re-ranking**
- ✅ 완료 기준: "군복무 크레딧이 뭐야?" → 관련 조문이 상위에 나온다

## 2단계. 혜택 조회 (MCP)
- [ ] 공공서비스(혜택) 정보 API 클라이언트 🔑 공공데이터포털
- [ ] 기관 링크 DB (보훈부, 제대군인지원센터, 병무청, 고용24 등)
- [ ] 위 두 가지와 법령 검색을 **MCP 서버**로 묶기
- ✅ 완료 기준: "제대군인" 검색 → 혜택 목록 + 신청 링크

## 3단계. 에이전트 (LangGraph)
- [ ] 상태 스키마 (대화, 프로필, 출처)
- [ ] 워커 4개: 프로필 / 규정 / 혜택 / 기관연계 (ReAct)
- [ ] **슈퍼바이저**: 질문을 보고 필요한 워커만 호출
- [ ] **근거 검증 노드** (Reflection): 출처 없는 내용 걸러내기
- [ ] 에러 처리와 폴백: API 실패 시 링크 안내로 대체
- [ ] 체크포인터(대화 기억), 프로필 장기 메모리
- [ ] **LangSmith** 연결해서 실행 과정 추적
- ✅ 완료 기준: 유형별 질문(병사 / 간부 / 장기 / 보훈)에 맞는 혜택을 근거와 함께 답한다

## 4단계. 서버와 화면
- [ ] FastAPI: `/chat` (SSE 스트리밍), `/profile`, `/health`
- [ ] 간단한 웹 채팅 화면 (HTML / CSS / JS)
- ✅ 완료 기준: 브라우저에서 질문하면 답변이 실시간으로 나온다

## 5단계. 평가와 배포
- [ ] 평가 질문 30개 만들기 (유형별로 고르게)
- [ ] LangSmith로 정확도, 응답 시간, 비용 측정 → 프롬프트와 검색 개선
- [ ] Docker 이미지
- [ ] AWS 배포 + GitHub Actions **CD** (자동 배포)
- ✅ 완료 기준: 공개 URL에서 서비스가 동작한다
