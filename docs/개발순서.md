- [x] 법령 수집기: 국가법령정보센터 API → 조문 단위로 자르기, 수집 목록 `data/laws.yaml`
- [ ] 지자체 조례 수집기 (자치법규) 🔑 법령 OC — 실제 응답 형식 확인 후 작성

- [x] 검색 고도화: **HyDE**, **Re-ranking** (LLM 실패 시 벡터 검색으로 대체)
- [x] 수집·검색 명령: `uv run jeonyeok-rag laws | files | search | stats`
- [ ] 실제 데이터로 수집하고 검색 품질 확인 🔑 법령 OC, Gemini
- ✅ 완료 기준: "군복무 크레딧이 뭐야?" → 관련 조문이 상위에 나온다

## 2단계. 혜택 조회 (MCP) — 코드 완료, 실제 데이터 대기
- [x] 공공서비스(혜택) 정보 API 클라이언트: 키워드별 조회, 중복 제거, 관련도 정렬, 지역 필터, 6시간 캐시
- [x] 기관 링크 DB 9곳 (`data/institutions.yaml`, URL 접속 확인)
- [x] 위 두 가지와 법령 검색을 **MCP 서버**로 묶기 (`uv run jeonyeok-mcp`, 도구 4개)
- [x] 폴백: API 실패 시 정부24·온통청년 등 기관 링크로 대체
- [ ] 실제 API 응답으로 필드 이름 확인 🔑 공공데이터포털
- ✅ 완료 기준: "제대군인" 검색 → 혜택 목록 + 신청 링크

## 3단계. 에이전트 (LangGraph) — 뼈대 완료, 실제 실행 대기
- [x] 상태 스키마 (대화, 프로필, 워커 결과, 출처) — 출처·결과는 질문마다 초기화
- [x] 워커 3개: 규정 / 혜택 / 기관연계 (`create_agent` ReAct, MCP 도구 연결)
- [x] 프로필 추출: 매 질문마다 대화에서 복무 정보 추출, 부족하면 **되묻기**(ask_user)
- [x] **슈퍼바이저**: 질문을 보고 필요한 워커만 호출, 최대 4회
- [x] **근거 검증 노드** (Reflection): 출처 없는 금액·기한·자격은 지우거나 "(확인 필요)"
- [x] 에러 처리와 폴백: 워커·라우터·검증 실패 시 그 단계만 건너뛰고 계속
- [x] 체크포인터(대화 기억), 프로필 장기 메모리(user_id 기준, 대화가 달라도 유지)
- [x] 터미널 대화: `uv run jeonyeok-chat`
- [ ] Gemini로 실제 실행해서 프롬프트 다듬기 🔑 Gemini
- ✅ 완료 기준: 유형별 질문(병사 / 간부 / 장기 / 보훈)에 맞는 혜택을 근거와 함께 답한다

## 4단계. 서버와 화면 — 완료, 실제 실행 대기
- [x] FastAPI: `/chat` (SSE: 진행 단계 → 답변/되묻기), `/profile/{user_id}`, `/health`
- [x] 에이전트를 못 띄워도(키 누락) 서버는 뜨고 `/chat`은 503으로 이유 안내
- [x] 화면을 **Next.js 16**으로 이전 (`frontend/`): 위쪽 메뉴, 첫 화면, 답변(혜택 카드·근거 자료), 데모 모드
- [x] Next.js `/api/*` → FastAPI 프록시 (SSE 실시간 전달 확인, 허용한 경로만 통과)
- [x] 반응형(모바일 메뉴), 다크 모드, `?q=` 공유 링크
- [x] 폴더 구조 `backend/` · `frontend/`로 분리, Docker Compose 두 서비스
- [ ] Gemini로 실제 대화 확인 🔑 Gemini
- ✅ 완료 기준: 브라우저에서 질문하면 답변이 실시간으로 나온다
