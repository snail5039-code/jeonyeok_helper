### 10-12 자료 보강과 검색 골든셋

**검색 골든셋** (`data/eval/retrieval_golden.yaml`, 66문항): 질문마다 상위 6개에 나와야 하는 근거를
조문·안내서 쪽·조례 이름으로 정하고(검색 결과를 베끼지 않음), 다른 지역 조례가 섞이면 실패로 본다.
`uv run jeonyeok-eval --retrieval --ablation`으로 검색 설정을 비교한다.

| 검색 설정 | Hit@6 | Recall@6 | MRR | 시간 |
|---|---|---|---|---|
| 벡터 검색만 | 97% | 97% | 0.75 | 0.4초 |
| + HyDE | 97% | 97% | 0.75 | 2.1초 |
| + HyDE + 재정렬 (서비스) | **100%** | **100%** | **0.83** | 3.7초 |

- 재정렬이 첫 근거의 순위를 끌어올린다(MRR 0.75 → 0.83). HyDE는 이 골든셋에서는 효과가 작았다.
- 처음 돌렸을 때 '실업급여'로 고용보험법을 못 찾았다. 후보를 30개로 늘려도 못 찾아서, 흔히 쓰는 말을
  법령 용어로 덧붙이는 `LEGAL_TERMS`(실업급여 → 구직급여 등)를 넣어 해결.

### 10-12 대화형 로드맵, 내 정보, B급 캐릭터

사용자 요청: 자연어로 답하면 이어서 준비 계획을 세워 로드맵을 그리고, 그 로드맵을 따라가며 어디까지 했는지 재밌게
보여 줄 것. 정보를 자세히 적는 창을 만들어 검색에 참고할 것. 그림은 B급 감성으로.

- **답변 → 할 일 (planner)**: 답변이 끝나면 빠른 모델이 답변과 근거 목록을 보고 할 일 0~3개를 뽑아 SSE `plan`으로
  보낸다. 할 일마다 근거 번호가 있어야 하고(없으면 버림), 이미 담긴 제목은 빼서 대화가 이어져도 중복이 안 쌓인다.
  근거가 없는 답(되묻기, 일반 안내)에서는 부르지 않는다
- **로드맵 저장**: Postgres `journey_item` 표(Alembic 0002). 사용자·제목이 같으면 한 번만. 기존 `POST /roadmap`은
  '내 정보로 한 번에 채우기'(`/journey/{id}/generate`)로 바뀌어 같은 표에 담긴다
- **내 정보**: 군, 계급, 특기, 학력, 주거, 목표(여러 개), 희망 직무, 자격증, 부상 여부, 메모. LangGraph 저장소의
  프로필에 넣고, 대화 시작마다 다시 읽어 대화 중에 고쳐도 바로 반영. 목표·희망 직무·자격증은 혜택 검색어로 쓴다
- **게임 요소**: 완료율에 따라 이병(0) → 일병(20) → 상병(45) → 병장(75) → 민간인(100%). 스티커: 첫 단추,
  정보통(내 정보 80%↑), 질문 폭격기(대화로 3개↑), 단계별, 전역 마스터
- **B급 그림**: SVG 마스코트 '전역이'(계급마다 표정·소품이 바뀌고 민간인이 되면 후드티), Jua 글꼴, 노란 종이 카드,
  굵은 검은 테두리와 밀린 그림자. 다크 모드에서는 테두리·그림자를 크림색(`--ink`)으로 바꿔 윤곽을 살림
- **화면**: 넓은 화면은 채팅 옆에 로드맵 패널(방금 담긴 할 일, 단계 지도, 스티커), 좁은 화면은 위쪽 진행 칩.
  할 일 카드의 '이 단계 진행하기'는 그 할 일을 채팅으로 이어서 묻는다
- 확인: 실제 서버로 Playwright 캡처(`docs/screenshots/1~7`). IT 취업 질문 하나에 할 일 2~3개가 근거와 함께 담김.
  백엔드 테스트 158개, 프런트 테스트(로드맵 계산 9개 추가)·타입·린트 통과
- **평가가 41/41 → 37/41로 떨어진 일**: 내 정보 항목(군·계급·목표·자격증 등)을 대화 추출 스키마에도 넣었더니
  '병장으로 전역'을 계급에만 넣고 복무 형태를 비우거나, 말하지 않은 목표('취업')·부상('없음')을 지어냈다.
  추출 스키마는 원래 6개 항목으로 되돌리고(자세한 항목은 내 정보 화면에서만), 이를 지키는 테스트를 추가 → 41/41.
  실제 서버 흐름 확인 13가지(내 정보 저장 → 채팅 plan → 중복 없음 → 완료·남의 할 일 404·빼기 → 한 번에 채우기) 통과

### 10-13 길잡이 대화: RAG 검색기에서 '길을 안내하는' 대화로

사용자: "rag 사용도 중요한데 자연어로 채팅해서 길을 안내해주는게 가장 중요해". 처음부터 끝까지 흐름을 같이 짚고
네 가지를 정함 → 계급은 끝낸 개수로, 할 일은 제안 후 골라 담기, 끝은 핵심 할 일 + 기한 D-day, 첫 시작은 채팅으로
하나씩. 답변은 한 걸음씩 + 펼치기.

- **coach 노드 (그래프 맨 앞)**: 이번 말을 검색 없이 바로 답할지(talk) 자료를 찾을지(research) 정한다. talk는 인사,
  진행 보고, 자기 정보만 말할 때, '다음 뭐 해요?', 복무 형태를 모르는 맞춤 혜택 질문뿐이고 나머지는 모두 research.
  talk 답은 1~2초 (검색 답은 15초 안팎)
- **버튼은 규칙으로**: 모르는 정보(복무 형태 → 지역 → 전역일)가 있으면 고르는 버튼, 없으면 다음 할 일과
  [했어요] [어떻게 해요?] [나중에]. 길잡이 말이 질문으로 끝나지 않거나 다음 할 일을 빠뜨리면 규칙으로 덧붙인다
- **guide 노드 (검색 답 뒤)**: 답변 위에 보일 "지금 이것부터" 한마디와 로드맵에 담을 할 일 제안(⭐핵심, 기한).
  제안은 저장하지 않고 사용자가 고른 것만 `POST /journey/{id}/items`로 담는다 (예전 planner 자동 담기 대체)
- **첫 로드맵 자동 생성**: 복무 형태·지역·전역일을 다 알고 로드맵이 비어 있으면 대화 끝에 만들고 첫 할 일을 권한다.
  이미 전역한 사람에게는 '전역 전' 단계를 빼도록 로드맵 프롬프트에 오늘 날짜를 넣음
- **기한 D-day**: LLM이 기한을 지어내기 쉬워서, 기한 문구가 근거 글에 그대로 있을 때만 남기고(`ground_deadline`)
  전역일 + 개월 수로 D-day 계산. 표: `journey_item`에 core·deadline·due_months (Alembic 0003)
- **계급**: 끝낸 개수(1 일병, 4 상병, 8 병장)로 올라 할 일이 늘어도 내려가지 않음. 핵심을 다 끝내면 민간인
- **화면**: 사용자 말풍선(오른쪽)과 전역이 말풍선(왼쪽). 검색 답은 '자세히 보기'로 접힘. 첫 화면도 전역이가 먼저
  말을 건다 (처음: 복무 형태 버튼, 다시 왔을 때: 다음 할 일과 D-day)
- **실제로 돌려 보며 고친 것**
  - '제대군인 취·창업지원 했어요'를 복무 형태(중·장기)로 읽음 → 버튼 동작이 있는 말은 프로필 추출을 건너뛰고,
    추출 프롬프트에 '제도 이름은 복무 정보가 아님' 추가
  - '어떻게 신청해요?'에 기관만 찾고 "자료에 없어요" → 신청 방법을 물으면 규정·혜택도 함께 찾도록 라우터 규칙 추가
  - coach가 '군복무 크레딧이 뭐예요?' 같은 질문도 talk로 답해 평가 28/41 → talk 조건을 다섯 가지로 좁히고
    애매하면 research
  - '했어요' 뒤에 다음 할 일 없이 끝나 대화가 멈춤 → talk 답에는 늘 다음 할 일을 붙임
  - 프롬프트를 좁혀도 '예비군 훈련, 어떻게 신청해요?'를 가끔 talk로 답함 → '어떻게·방법·서류·자격·얼마·신청·
    어디서' 같은 말이 있으면 규칙으로 바로 research (`needs_research`)
  - 이미 담긴 '장병내일준비적금 수령'과 거의 같은 '…정부지원금 수령'을 또 제안 → 앞 6글자 이상 같으면 같은 할 일로
- 평가: 길잡이 문항 3개 추가(자기 정보 말하기·감사 → talk), '안녕하세요'는 이제 복무 형태를 되묻는 것이 정답
  → 44문항 43/44 (99%), 평균 16.2초. talk 답은 약 2초. 남은 1개(t01 '병장 전역자'를 병사로 못 읽음)는
  프로필 추출이 가끔 흔들리는 것으로, 단독 실행에서는 통과
- 실제 서버 흐름 캡처: 첫 방문 → 버튼 3번 → 로드맵 자동 생성 → '어떻게 해요?' → 담기 → '했어요' → 다음 할 일
  (`docs/screenshots/guide_*`)
- 남은 것: 할 일 문장이 복무 형태와 안 맞게 나오는 경우가 있음 (병사에게 '5년 이상 복무하셨다면' 같은 말)

### 10-13 쓸모 있는 답, 되돌리기, 화면 점검

사용자 지적 세 가지와 화면 전체 점검.

- **"전역 후 혜택 있어요?"에 '정부24에서 조회해 보세요'로 끝남**: 서비스를 쓸 이유가 없는 답이었다. 원인은 둘.
  ① 복무 형태를 모르면 라우터가 되묻고, 질문이 'talk'로 빠져 검색을 안 함 ② 기관 안내 한 줄만 있는 것을
  '할 일'로 제안함. 고친 것: 복무 형태를 몰라도 되묻지 않고 **병사 기준으로 바로 찾고** 첫 문단에 "의무복무 병사
  기준으로 정리했어요"라고 밝힘(화면이 따로 복무 형태 버튼을 보여 줌), 답변 프롬프트에 "사이트로 떠넘기지 말고
  구체적인 제도 이름과 내용으로" 추가, 근거가 기관 안내뿐인 할 일 제안은 버림, 혜택·'뭐 받' 같은 말이 있으면
  규칙으로 검색, 규정 워커가 혜택 전반 질문에는 대표 제도를 하나씩 찾음. 평가 g01은 '되묻기'에서 '구체적인 혜택으로
  답하기'로 바꿈
- **임무 1개 끝내자마자 민간인**: 핵심 임무가 1개뿐일 때 그것을 끝내면 '핵심을 모두 끝냄'이 되어 이병에서 바로
  민간인이 됐다. 이제 핵심 3개 이상이고, 병장 수준(8개)까지 끝냈거나 전부 끝냈어야 민간인(`toCivilian`).
  남은 개수도 이 기준으로 안내
- **되돌리기**: 완료·빼기·담기·내 정보로 만들기를 모두 기록(`useJourney`의 history). 변경 직후 10초 알림의
  [되돌리기], 작전도 화면 '변경 기록'에서 "여기까지 N개 되돌리기"로 여러 단계를 한꺼번에(방향을 틀 때).
  빼기를 되돌리면 완료 여부와 출처까지 그대로 복원(백엔드 `POST /journey/{id}/items`가 done·origin을 받음).
  되돌린 임무는 새 id가 되므로 옛 id를 새 id로 바꿔 부르는 표를 둠
- **화면 점검** (데스크톱·태블릿·모바일·다크 × 임무 있음·없음 × 3개 화면, 가로 넘침·콘솔 오류·잘린 글 자동 검사 +
  눈으로 확인): 다크 모드를 직접 켜면 위 메뉴가 밝은 바탕에 밝은 글자로 안 보임(Tailwind `dark:`가 시스템
  설정만 따라서) → 색 토큰(`--bar-1/2`)으로 교체, 내 정보 저장 막대가 가로로 꽉 차 내용을 가림 → 내용만큼만,
  작전도가 비었을 때 비활성 버튼 이유 안내 추가, 모바일 입력창 안내문 잘림 → 짧게, 완주 안내 문구 정정
- 되돌리기 흐름은 실제 브라우저로 확인(완료 → 되돌리기, 빼기 → 되돌리기, 3단계 한꺼번에)
- 계속 흔들리던 t01('병장 전역자'를 병사로 못 읽음): 추출 프롬프트에 "이병·일병·상병·병장이면 service_type=conscript" 추가
- **평가**: 답변 44문항 43/44 → t01 수정 뒤 통과(마지막 실행 전 개별 확인 5/5), 검색 골든셋 69문항 Hit@6 100%·MRR 0.84.
  처음 돌린 검색 평가의 오류 2건(Hit 97%)은 다른 작업과 동시에 돌려 요청이 몰린 탓이었고 다시 돌리니 오류 0

## 주요 결정과 이유

| 결정 | 이유 |
|---|---|
| LLM은 **Gemini** | 사용자가 보유한 키. 기본 2.5 Flash, 필요하면 3.5로 교체 |
| 기술 스택은 **AI.M 1기 AI 에이전트 엔지니어 트랙** 기준 | LangGraph 멀티에이전트, MCP, RAG(HyDE·Re-ranking), FastAPI, Docker, CI/CD |
| 대상은 **전역자 전체 유형** | 병사·단기 간부·중장기·보훈대상자. 유형마다 혜택이 달라 프로필로 먼저 구분 |
| 프로필은 **대화 중에 묻기** | 정보가 부족할 때만 되묻고, 받은 정보는 장기 메모리에 저장 |
| **MCP 1.x 고정** | LangChain MCP 어댑터가 MCP 2.x를 아직 지원하지 않음 |
| 화면은 **Next.js** (Flutter 아님) | 링크로 바로 쓰는 웹이 전역자 사용 패턴에 맞고, 검색·공유에 유리 |
| Next.js → FastAPI는 **Route Handler 프록시** | 실행 시 `API_URL`을 읽어 이미지 하나로 배포 가능, SSE를 버퍼링 없이 전달 |
| **LangSmith 대신 평가 데이터셋** | 사용자 요청. 30문항을 근거 출처·답변 핵심어·프로필·되묻기로 채점 |
| 평가는 **정답 문장이 아닌 근거와 행동** 기준 | 금액·기한은 법령 개정으로 바뀌고, 기준을 잘못 적으면 그 자체가 오류가 됨 |
| 모델은 **2.5 Flash 유지** | 데이터를 넣은 뒤 30/30이 나와 3.5로 올릴 이유가 없음 |
| **조례는 사용자 지역 것만 검색** | 지자체마다 비슷한 조례가 수백 개라 섞으면 법령이 밀려남. 지역을 모르면 법령만 |
| **행정규칙은 이름으로 골라 수집** | 보훈부·국방부 훈령 대부분이 내부 운영 규정이라 키워드 수집은 잡음이 많음 |
| **지자체 장학금은 제외** | 약 1,000건이지만 운영 지역을 안정적으로 알 수 없어 지역 필터를 못 검. 전국·군 관련 148건만 |
| 전체 목록을 받아 **캐시하고 직접 거름** (위탁병원·나라사랑가게·청년정책) | 이 API들은 지역 조건 검색이 없음. 하루(청년정책은 12시간) 캐시 |
| 보훈관서 주소록은 **직접 정리한 YAML** | 공개 API가 없어 국가보훈부 누리집 관서별 페이지에서 수집 |
| **워커는 도구를 반드시 부르고, 결과를 다시 요약하지 않음** | 답변·검증은 도구 원문(evidence) 기준. 요약은 시간만 들고, 도구 없이 답하면 근거가 없어 검증에서 지워짐 |
| **답변 생각 예산 1024** | 평가 비교: 기본값 30/30 27초, 1024 30/30 21초, 0 29/30 18초('혜택 다 알려줘'에 답이 좁아짐) |
| **스트리밍은 초안 → 검증본 교체** | 검증 전 초안을 먼저 보여 주되, 근거 확인이 끝나면 최종 답으로 바꾸고 그때 출처를 붙임 |
| 전직교육 안내서는 **사용자가 받아 줌** | 내려받으려면 사이트 이용약관 동의가 필요해 대신 받지 않음. 2025년판은 글자 정보가 없어 Gemini로 한 쪽씩 옮겨 적음(`rag/transcribe.py`) |

## 실제로 돌려 보며 찾은 문제와 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| 질문을 보내도 첫 화면이 사라지지 않음 | 아이콘 `<symbol id="home">`과 화면 영역 `id="home"`이 겹침 | 아이콘 id에 `ic-` 접두어, id 중복 검사 테스트 |
| 장기 메모리(프로필)가 저장되지 않음 | `from __future__ import annotations`가 있으면 LangGraph가 노드에 저장소를 주입하지 못함 | 해당 파일에서 제거하고 주석으로 기록 |
| 답변 카드가 깨짐 (줄바꿈 사라짐) | 근거 검증 단계가 답변을 다시 쓰며 줄바꿈을 날림 | 문제가 없으면 초안을 그대로 사용 |
| 3.5가 근거 없는 혜택·금액·연락처를 지어냄 | 검증이 도구 원문이 아니라 워커 요약을 기준으로 함 | 도구 원문(evidence)을 답변·검증의 기준으로 |
| 법령 API "사용자 정보 검증 실패" | OC 값이 실제 계정과 다름 (IP 등록은 정상) | 사용자가 OC를 바로잡아 해결 |
| 검색 시 "Error loading hnsw index" | Windows에서 경로에 한글이 있으면 Chroma가 인덱스 파일을 쓰지 못함 | 한글 경로면 `LOCALAPPDATA` 아래 영문 경로에 저장 |
| 지역 필터가 다른 지역 혜택을 못 거름 | 실제 소관기관유형은 `시군구`·`광역시도`인데 '지방'이라는 글자로 찾음 | 실제 값으로 구분 |
| 조례 3개 저장 실패 | 한 조례 안에 같은 조문 번호가 두 번 나옴 | 같은 번호는 본문을 이어 붙여 하나로 |
| 라우터가 법령 질문에 검색 없이 바로 답함 | 빠른 설정(생각 끔) 라우터의 판단 | '워커 없이 answer 금지', 자격·기간 질문은 규정 검색 규칙 |
| 동시에 돌린 워커가 서로를 기다림 | MCP 도구가 동기 함수라 이벤트 루프를 막음 | 도구를 스레드에서 실행 |
| 브이넷 채용 지역이 엉뚱하게 나옴 | 공식 안내의 지역 코드표가 실제 응답과 다름 (4가 부산이 아니라 인천) | 1~18을 모두 호출해 확인한 코드로 |
| 나라사랑가게 호출 방법을 알 수 없음 | 포털 상세 페이지 명세가 비어 있음 | 페이지에 숨어 있던 Swagger 명세에서 오퍼레이션 확인 |
| 온통청년 403 | 기본 User-Agent(python-httpx)를 막음 | 브라우저 User-Agent 사용, 오류 메시지에서 인증키 URL 제거 |
| 자료를 늘린 뒤 30/30 → 24/30 | ① 606조각 안내서가 법령을 밀어냄 ② 워커가 도구 없이 답해 검증에서 답이 지워짐 ③ '병역필' 요건을 군 관련으로 봄 | 같은 문서는 검색 결과 2개까지, 워커 도구 호출 강제, '병역' 제외 |

## 지금 구조

```
브라우저 ─▶ Next.js (frontend) ─/api/*─▶ FastAPI (backend, SSE: step → delta → answer)
                                           └─ LangGraph 슈퍼바이저
                                                ├─ 프로필 추출 (빠른 설정)
                                                ├─ 라우팅 (빠른 설정, 혜택 질문은 규정도 함께 동시 실행)
                                                ├─ 규정 워커 ─ MCP ─ RAG (pgvector, HyDE, Re-ranking, 같은 문서 2개까지)
                                                │                  법령·행정규칙·해석례·조례(지역)·민원·장학금·안내서
                                                ├─ 혜택 워커 ─ MCP ─ 정부24 혜택, 온통청년, 브이넷 채용, 보훈 채용, 나라사랑가게
                                                ├─ 기관 워커 ─ MCP ─ 기관 링크 DB, 관할 보훈관서, 보훈 위탁병원
                                                ├─ 답변 작성 (도구 원문 기준, 생각 예산 1024, 스트리밍)
                                                └─ 근거 검증 (도구 원문 기준, 문제 있을 때만 다시 씀)
벡터 검색·피드백: PostgreSQL(pgvector) / 대화 기록·프로필: SQLite / 실행: Docker Compose / CI: GitHub Actions
```
