# 집 PC 서버 + Cloudflare Tunnel 배포 (같이 진행하는 순서)

> **2026-10-24: 진행하지 않기로 했습니다.** 실제 서버는 만들지 않고, AWS에 올리는 순서만 [AWS에 올리기](AWS_배포.md)에 정리했습니다. 아래는 참고용으로 남겨 둡니다.

> 2026-10-20 정리. [배포 가이드](배포_가이드.md)의 **방법 F**를 실제로 따라 하는 순서입니다.
> 결정한 것: 우선 **집 PC를 서버로**, 공개는 **Cloudflare Tunnel**, 주소는 **싼 도메인을 사서** 고정합니다.
> 각 단계의 **(직접)** 은 내가 하는 것, **(Claude)** 는 레포에서 코드로 하는 것입니다.

## 왜 이렇게 하나

- 백엔드가 메모리를 약 **855MB** 씁니다(2026-10-20 측정). 그중 **Kiwi 형태소 분석기가 약 500MB**, 라이브러리 약 130MB, BM25 색인과 실행 중 데이터가 약 225MB입니다. 그래서 512MB 무료 서버에는 못 올리고, 유료 서버는 월 $20 이상이 듭니다.
- 임베딩(10,143 조각 × 3072차원, 154MB)은 **DB(pgvector)에 있어서** 백엔드 메모리는 거의 안 씁니다. 질문을 벡터로 바꾸는 건 Gemini API가 합니다.
- 집 PC는 메모리가 넉넉하고 비용이 **도메인값만** 듭니다. 실기기 테스트(알림·아이폰 설치·캘린더)를 먼저 해 보기에 좋습니다.

## Cloudflare Tunnel이 하는 일

```
사용자 휴대폰 → 인터넷 → Cloudflare ═(터널)═ 내 PC의 docker compose (web:3000)
```

- 내 PC가 Cloudflare 쪽으로 **먼저 연결을 걸어 두기** 때문에 공유기 포트를 열 필요가 없습니다. 공개되는 건 화면(`web`) 하나뿐이고 DB·PC의 다른 곳은 열리지 않습니다.
- **HTTPS**(자물쇠)를 Cloudflare가 붙여 줍니다. 알림·홈 화면 설치는 HTTPS에서만 됩니다.
- 집 IP가 드러나지 않고, 몰려드는 공격(DDoS)·봇을 어느 정도 걸러 줍니다.
- 자체 구축(직접 운영)이라면 이걸 공인 IP + 포트 개방 + Caddy/Nginx + Let's Encrypt + 방화벽으로 직접 합니다. 서버로 옮길 때는 [배포 가이드 4장](배포_가이드.md#4-방법-a-aws-lightsail-추천) 방식입니다.

## 무료 도메인을 안 쓰는 이유

- Cloudflare 고정 터널은 **도메인 전체의 관리 권한(네임서버)** 을 Cloudflare에 맡겨야 합니다.
- DuckDNS 같은 무료 도메인은 `내이름.duckdns.org`처럼 **남의 도메인 밑의 이름**이라 맡길 수 없습니다.
- Freenom(.tk 등)은 2023년에 사실상 문을 닫았고, eu.org는 되지만 승인에 며칠~몇 주가 걸립니다.
- 그래서 **싼 도메인을 사는 게 가장 간단합니다**(첫해 몇천 원~연 1.5만 원).

## 0단계: 미리 해 보기 (가입 없이, 선택)

도메인 없이 임시 주소로 바로 확인할 수 있습니다. 주소는 켤 때마다 바뀌어서, 알림 구독·홈 화면 앱은 다시 해야 합니다.

```bash
winget install --id Cloudflare.cloudflared
```

```bash
cloudflared tunnel --url http://localhost:3000
```

출력에 나오는 `https://xxxx.trycloudflare.com`을 휴대폰에서 엽니다.

## 1단계: 도메인 사기 (직접)

1. https://dash.cloudflare.com 가입·로그인
2. **Domain Registration → Register Domains**에서 이름 검색
3. **갱신 가격**까지 확인하고 결제 (Cloudflare는 원가 판매라 첫해와 갱신 가격이 같음)

- 다른 곳(Porkbun·Namecheap·가비아)에서 사도 됩니다. 첫해만 싸고 **갱신 때 비싸지는** 경우가 많으니 확인하고, 산 뒤 네임서버를 Cloudflare 것으로 바꿉니다.
- 이름은 짧게, 하이픈 없이. 예: `jeonyeok.xyz`

## 2단계: 터널 만들기 (직접)

1. Cloudflare 대시보드 → **Zero Trust → Networks → Tunnels → Create a tunnel**
2. 종류는 **Cloudflared**, 이름은 `jeonyeok-home`
3. 설치 방법 화면에 나오는 **토큰**(긴 문자열)을 복사해 둡니다. 비밀값이라 Git·채팅에 올리지 않습니다.
4. **Public Hostname** 추가
   - Subdomain: `app` (또는 비워서 도메인 그대로)
   - Domain: 산 도메인
   - Service: `HTTP` → `web:3000` (터널을 compose 안에서 돌리므로 컨테이너 이름으로)

## 3단계: 레포 준비 (Claude)

| | 할 일 |
|---|---|
| ☐ | `docker-compose.yml`에 `cloudflared` 서비스 추가 (토큰은 `.env`의 `CLOUDFLARE_TUNNEL_TOKEN`에서 읽기) |
| ☐ | DB 비밀번호를 `.env`의 `POSTGRES_PASSWORD`로 (지금은 `jeonyeok`이 파일에 적혀 있음) |
| ☐ | 이용약관·개인정보처리방침 화면 |
| ☐ | `web`의 `3000:3000` 공개 포트는 터널이 있으니 로컬 확인용으로만 남기거나 `127.0.0.1:3000:3000`으로 |

## 4단계: `.env` 채우기 (직접, Claude가 안내)

`backend/.env`에 추가·수정합니다. 값은 Git에 올리지 않습니다.

| 키 | 값 |
|---|---|
| `CLOUDFLARE_TUNNEL_TOKEN` | 2단계에서 복사한 토큰 |
| `POSTGRES_PASSWORD` | 새로 만든 긴 값 |
| `VAPID_SUBJECT` | `https://app.내도메인` (경로 없이) |
| `ADMIN_TOKEN` | 운영용으로 새로 생성 |

## 5단계: 띄우기

```bash
docker compose up -d --build
```

```bash
docker compose ps
```

- 모두 `healthy`(cloudflared는 `running`)인지 보고, 휴대폰에서 `https://app.내도메인`을 엽니다.
- DB 비밀번호를 바꾸면 기존 DB 볼륨은 예전 비밀번호로 만들어져 있습니다. 처음 한 번은 DB 안에서 비밀번호를 바꾸거나, 덤프 → 볼륨 새로 만들기 → 복원 순서로 합니다(그때 같이 진행).

## 6단계: 집 PC 설정 (직접)

| | 할 일 |
|---|---|
| ☐ | **절전 끄기**: 설정 → 시스템 → 전원 → 화면·절전을 "안 함" |
| ☐ | **Docker Desktop 자동 시작**: Docker Desktop 설정 → General → *Start Docker Desktop when you sign in* |
| ☐ | **재부팅 시간 조절**: Windows 업데이트 → 사용 시간 설정 |
| ☐ | compose 서비스는 `restart: unless-stopped`라 Docker가 켜지면 같이 살아납니다 |

## 7단계: 실테스트

[배포 가이드 6장](배포_가이드.md#6-배포-후-실테스트-체크리스트) 체크리스트를 휴대폰·PC로 하나씩 확인합니다. 여기에 더해:

| | 확인 |
|---|---|
| ☐ | `/admin`의 질문 기록에서 사용자별 횟수 제한이 실제 접속자 IP 기준으로 걸리는지 (터널을 거치면 IP 전달 방식이 달라질 수 있음) |
| ☐ | PC를 재부팅한 뒤 로그인만 하면 서비스·터널이 다시 뜨는지 |

## 8단계: 운영하면서 채울 것

- **백업**: 매일 `pg_dump`를 다른 디스크나 클라우드 드라이브로. 집 PC 디스크가 고장 나면 DB가 날아갑니다.
- **살아 있는지 확인**: UptimeRobot(무료)으로 `https://app.내도메인/api/health`를 5분마다.
- **비용**: Gemini 결제 한도·알림.
- 사용자가 늘거나 PC를 계속 켜 두기 어려우면 [배포 가이드](배포_가이드.md)의 Lightsail·Oracle 무료로 옮깁니다. 덤프 하나로 그대로 옮겨집니다.

## 막혔을 때

| 증상 | 원인과 해결 |
|---|---|
| `api`가 계속 재시작, 로그에 `Can't locate revision identified by '0008'` | DB는 최신 마이그레이션인데 Docker 이미지가 예전 것. `docker compose build api` 후 다시 띄우기 |
| 터널 주소에서 502 | `web`이 아직 안 떴거나 Public Hostname의 서비스 주소가 틀림 (`web:3000`인지) |
| 알림이 안 옴 | `VAPID_SUBJECT`가 지금 주소인지, 주소를 바꿨다면 알림을 다시 켰는지 |
| Git Bash에서 `curl`로 한글 질문을 보내면 엉뚱한 답 | 한글이 UTF-8로 안 넘어간 것. 질문을 UTF-8 파일로 만들어 `--data-binary @파일`로 보내기 |
