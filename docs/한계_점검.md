# 한계 점검 (2026-10-13)

추측이 아니라 **재 보거나, 실제 서버에 입력을 넣어 보거나, 코드를 열어서** 확인한 것만 적었습니다.
"고침"은 이 점검에서 바로 고친 것, "남음"은 고치지 못한 것과 이유, 고치려면 무엇이 필요한지입니다.

## 1. 속도

| 구간 | 측정 | 상태 |
|---|---|---|
| 첫 작전도 (전역일 답한 뒤) | 이전 20~30초 → **약 15초** | 고침 |
| 인사·진행 보고 | 2~3초 | 문제 없음 |
| 일반 질문 (근거 찾아 답) | 평가 63문항 평균 18초, 서버가 바쁘면 20~40초 | 남음 |

**첫 작전도를 줄인 방법** (자료 모으기 6~7초 + 정리 12~14초였음)
1. 정리 모델을 답변용에서 빠른 모델로 바꿈: 13.7초 → 7.6초. 임무 수와 핵심 수는 같은 수준(9~10개, 핵심 5개)
2. 같은 조건(복무 형태·지역·나이·계획·학력)이면 모은 자료를 30분 재사용. 전역일은 자료 모으기에 쓰이지 않음
3. 지역을 답한 시점에 백그라운드로 자료를 미리 모음 → 마지막 질문 뒤에는 정리만 함

**일반 질문이 느린 이유** (남음): 모델 호출이 순서대로 4~6번 일어납니다(프로필 추출 → 길잡이 판단 → 라우팅 → 워커 도구 호출 → 답변 → 근거 검증 → 길잡이 한마디). 초안은 스트리밍으로 먼저 보이지만 최종 답까지는 걸립니다.
줄이려면 근거 검증과 길잡이 한마디를 병렬로 돌리거나, 단순한 질문은 검증을 건너뛰는 설계 변경이 필요한데, 근거 검증이 환각을 막는 핵심 장치라 정확도 평가를 다시 해야 합니다.

## 2. 답의 품질

| 한계 | 확인한 것 | 상태 |
|---|---|---|
| 보훈대상자로 잘못 읽음 | "의병전역했는데 보훈 등록 가능?"을 이미 등록한 보훈대상자로 저장한 적이 있음(재현은 불안정: 같은 입력 3번 중 0번). 등록했다고 말해야만 인정하도록 규칙 추가 | 고침(방어) |
| 전역한 사람에게 복무 중 제도 | 2025-08 전역자의 작전도에 장병내일준비적금(복무 중 가입)이 나옴 → 거름 | 고침 |
| 쓸모 없는 임무 | "정부위원회 청년위원 확대" 같은 정책 기구가 임무로 담김 → 거름 | 고침 |
| 복무 형태와 안 맞는 임무 | 병사에게 5년 이상 복무자용 제도 → 거름 | 고침 |
| 엉뚱한 출처가 보임 | 근거 18개 중 본문이 인용한 것은 일부 → 인용한 것만 앞에 보이고 나머지는 접음 | 고침 |
| 같은 질문의 근거가 흔들림 | 평가 `m03`: 검색은 법 조문을 3·4위로 찾는데, 워커가 법령해석례를 골라 근거가 해석례로 잡힘 | 남음 |
| 기관명이 출처 제목에 없음 | 평가 `t10`: 장학금 답은 맞지만 출처 제목에 한국장학재단이 없어 채점에 걸림 (채점 기준 문제일 수도 있음) | 남음 |
| 지역이 시·도까지만 저장됨 | "부산 해운대 살아요" → 프로필 region이 `부산` (구·군이 사라짐). 구·군 조례 검색에 쓰이지 못할 수 있음 | 남음 |
| 사회복무요원·카투사 구분 약함 | 사회복무요원이 의무복무 병사로 저장되고, 답에 다른 지역(경기도) 사회복무요원 제도가 섞임 | 남음 |
| 영어 질문 | 한국어로만 답함(영어 입력에도 한국어로 되묻기) | 남음, 한국어 전용 서비스라 설계 범위 |

**점검 도중 바로잡은 내 실수**: 처음에 "중사 9년차·내년 3월 전역을 병사·올해로 읽는다", "프롬프트 주입 문장에 프로필이 오염된다", "날씨 질문을 인사로 착각한다"를 결함으로 적었지만, 터미널(Git Bash)의 `curl`이 한글을 깨뜨려 보낸 **테스트 도구의 오류**였습니다.
한글이 깨지지 않는 방식(UTF-8 파이썬)으로 수정 전 코드에 다시 넣어 보니 중사는 중·장기·2027-03으로 처음부터 정확히 읽었고, 주입·날씨 입력에도 프로필이 오염되지 않았습니다. 해당 보정 규칙은 걷어냈습니다.
이 일로 얻은 교훈: 한글 입력 테스트는 반드시 UTF-8을 보장하는 도구로 하고, 재현되지 않는 결함은 고치지 않는다.

## 3. 평가 방식의 한계

- 답변 평가는 **키워드와 출처 이름**으로 채점합니다. 문장이 틀려도 핵심 단어가 있으면 통과할 수 있고, 맞아도 단어가 다르면 떨어집니다(`h13`이 그랬음: "해당되지 않습니다"를 못 알아봄).
  모델이 채점하는 방식(LLM 판정)이나 사람이 보는 평가는 아직 없습니다.
- 표본이 작습니다: 답변 63문항, 검색 84문항. 같은 문항도 실행마다 결과가 조금 다릅니다(검색 MRR 0.84~0.85, `r83`은 한 번은 놓치고 한 번은 찾음, 같은 `h17`이 API에서는 통과하고 평가에서는 실패하던 일이 있었음 → 원인은 규칙이 검색 경로로 먼저 보내던 것).
- CI(GitHub Actions)는 테스트·린트·빌드만 돌리고 **평가는 돌리지 않습니다**(Gemini 키가 필요). 프롬프트를 바꾸고 평가를 안 돌리면 퇴보를 못 잡습니다.

## 4. 자료의 범위와 신선도

- 법령·조례·해석례는 **한 번 받아 둔 것**입니다. 법이 바뀌어도 자동으로 갱신하지 않습니다(수집 명령을 다시 돌려야 함).
- 공식 근거를 못 찾아 **넣지 못한 것**([추가할 자료](추가할_자료.md)에 근거와 함께 적음):
  - 보훈 등록 전 진료비(전역 6개월 이내 신청), 2026-08 확대된 제대군인 법률구조의 세부 요건
  - 2026 고용 우수기업 명단(보도자료가 PDF 첨부뿐), 전역 후 건강보험 자격·신고
  - 청년미래적금, 청년 마음건강 바우처(정부24·온통청년 API에 있는지 아직 확인 안 함)
- 공공누리 4유형(상업적 이용·변경 금지)인 제대군인지원센터 안내 기사는 보류했습니다.
- 아직 연동하지 못한 API: 고용24 훈련과정(인증키 심사 필요), Q-Net 자격시험 일정, 잡알리오 공공기관 채용.
- 보훈 쪽 공공데이터는 이미 쓰는 채용·위탁병원 외에 붙일 만한 것이 거의 없었습니다(통계·명단·법령 목록).

## 5. 운영과 보안

| 한계 | 확인한 것 | 상태 |
|---|---|---|
| 요청 제한 없음 | 코드 전체에 제한 장치가 없었음. 공개하면 `/chat`을 반복 호출해 Gemini 쿼터와 비용을 소진시킬 수 있음 | **고침**: 사용자(없으면 접속 주소)별 1분 20회, 넘으면 429와 안내 문구. `CHAT_RATE_LIMIT_PER_MINUTE`로 조정, 0이면 끔 |
| 로그인 없음 | 브라우저에 저장한 랜덤 ID가 곧 열쇠. 그 ID를 아는 사람은 내 작전도와 내 정보를 읽고 고칠 수 있음. 브라우저를 바꾸면 다른 사람 | 남음 |
| 내 정보 삭제 | 항목 빼기와 칸 비우기만 있고, "내 정보·대화 전부 삭제"가 없음. 대화 기록은 스레드 ID로 저장돼 사용자별로 지우기 어려움 | 남음, 공개 전에 필요 |
| 서버 한 대만 가능 | 대화 기록·프로필이 SQLite 파일(도커 볼륨)에 저장됨 → 서버를 여러 대로 늘릴 수 없음 | 남음, Postgres로 옮기면 해결(벡터·로드맵은 이미 Postgres) |
| 관측 도구 없음 | 로그만 있고 호출 수·실패율·응답 시간·모델 비용을 보는 곳이 없음 | 남음 |
| 배포 안 함 | Docker Compose로 로컬에서만 검증. AWS는 비용 결정이 필요해 보류 | 남음 |
| 입력 길이 | 질문 2,000자 제한은 있음 | 문제 없음 |

## 6. 화면

- 한국어 전용입니다.
- 키보드·스크린리더 접근성은 일부(aria 표시, 포커스 표시)만 확인했고 체계적으로 점검하지 않았습니다.
- 화면 점검은 데스크톱·태블릿·모바일·다크 조합에서 가로 넘침과 콘솔 오류가 없는 것까지 확인했습니다.

## 7. 다음에 하면 효과가 큰 순서

1. **내 정보·대화 삭제 기능** (공개하려면 필수, 작음)
2. **평가를 CI에 넣기** (퇴보를 바로 잡음. 키를 CI 비밀 값으로 두고 핵심 20문항만)
3. **대화 기록을 Postgres로** (서버 확장과 삭제 기능이 같이 풀림)
4. 근거 검증과 길잡이 한마디 병렬화 (일반 질문 속도, 평가로 정확도 확인 필요)
5. 못 넣은 공식 자료 보강, 고용24·Q-Net API 연동
6. 모델이 채점하는 평가 추가 (키워드 채점의 한계 보완)
